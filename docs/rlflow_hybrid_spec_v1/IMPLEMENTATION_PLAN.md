## 1. 实施原则

每个任务交付一个可测试的纵向切片；保留现有角色/预算/隔离不变量，先加观测出口再替换运行路径。没有必要不移动既有 Python 文件；模块边界可先通过小类/函数和 protocol 形成。

开发角色也遵循一个 writer 与独立 reviewer：写代码与审查不得由同一会话完成。只读调查可并行，共享接口先确定。PR 合并前绑定测试与实际 commit；不同代码的历史测试结果不得当成本 PR 证据。

## 6. 质量策略

单元测试覆盖纯 policy、reducer、预算、schema、cursor、版本校验；集成测试覆盖真实数据库事务、adapter fake、SSE 接缝和命令身份；E2E 覆盖浏览器 UI、移动视口、断线、重复点击、历史与 live 隔离。实际 Codex/GPU smoke test 单独标记、单独授权，不混入默认离线测试。

使用 model-free fixture 进行功能、并发与24小时稳定性测试；用小而真实的批准任务验证 runtime 语义。fixture 不能证明供应商接口强制权限，真实短运行也不能证明长期资源稳定，两者分别验收。
