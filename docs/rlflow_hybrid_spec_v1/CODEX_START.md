# 给 Codex 的开发启动指令

将本目录放在仓库 `docs/hybrid-v1/` 后，可以直接使用以下指令。此指令默认只覆盖 M0/M1，避免一次性大重写；后续开发范围通过同一需求合同扩展。

---

请基于 `docs/hybrid-v1/PRD.md`、`IMPLEMENTATION_PLAN.md` 和 `SOURCES.md`，在现有 rlflow 上实现 Hybrid 与真实实时 Dashboard 的第一阶段 M0/M1。

先确认本地 HEAD、工作树、现有架构、测试基线和资源边界。参考基线是 `90fd977f0ebcd3d00a5ce50c64f7ecb9a5009dae`，但不得覆盖其后的本地改动。若本地结构与文档不同，以实际代码建立映射，记录差异，保留需求不变量。

本阶段目标是：兼容性与安全能力矩阵；版本化事件/命令/目标 schema；增量投影与快照；现有运行器真实事件桥；snapshot+SSE 断线追平；真实 Live 页面与事件驱动动效。不要更换真实训练后端，不重写整个 engine，不接入 Jev，不添加新的长期 Commander，不增加用户需要选择的 Managed/Native 模式。

架构必须维持：rlflow 是唯一长期状态与授权权威；模型输出只是建议；单工作区一个 writer；独立 reviewer；预算与 UNKNOWN 在重启后不归零；Dashboard 不执行 shell；UI 活动、数字和完成状态来自可追溯事实。

在计划中按 T00–T08 拆分可测试提交，指出每项修改的现有文件和新增模块，不为了目录整洁搬迁所有文件。只读调查可并行；修改同一候选工作区只允许一个会话。实现与审查使用不同会话。

验证 Codex 本地版本、正式文档与实际协议，不把本需求中的 adapter 方法误当成 OpenAI API。用 `probe_capabilities` 与测试记录支持范围；没有真实权限/子代理可观测性证据时使用安全降级，不靠 AGENTS.md 声明冒充隔离。M0 不需要付费调用即可完成的检查先做；需要真实模型/GPU 的检查单独提出精确运行提案。

实现真实事件链路后再做视觉。fixture 仅用于测试与明确标识的演示，不能进入 live endpoint；无真实事件时计数不递增；断网停止业务流动并标记过期；初次追平不重播大量旧动画。不要整体复制 live-panel 示例视觉；自行设计 rlflow 布局，复用代码须保留许可与出处。

为 snapshot→SSE 接缝、重复/乱序事件、旧游标、慢客户端、模型 usage 缺失、失联、空闲页面、减少动画、移动端添加测试。现有状态更新不得每次重放或导出全部历史；大日志不嵌入领域事件。

默认不得启动真实 GPU 训练、调用付费模型、修改正在运行的生产账本、扩大网络权限或公开监听端口。允许在已有授权和隔离开发环境中安装必要开发依赖并锁定版本；不要改宿主全局环境或凭据。

每个切片实现后运行对应测试，交给独立 reviewer；有证据的普通开发问题在范围内自行解决，不逐步询问用户。真正涉及范围扩大、不可逆操作、未知生产执行或不可保证的安全边界时，给出阻塞事实和最小决策。

最终提供修改摘要、commit/文件映射、测试结果、资源观察、真实与 fixture 演示步骤、未验证能力、回滚方式及 `M1_ACCEPTANCE_REPORT.md`。不要只提供截图或“完成”声明。本阶段没有授权重构 M2–M5，完成后停止在阶段范围边界。

---

后续进入 M2 时，继续使用同一需求文件，仅批准对应任务集合及资源；不要重新建立另一套调度流程。
